# افزودن هاست VMware ESXi

## چرا ایجنت معمولی کار نمی‌کند

ایجنت پنل با فایل‌های `/proc` لینوکس کار می‌کند:

| فایل | برای چه |
|---|---|
| `/proc/stat`، `/proc/cpuinfo` | پردازنده |
| `/proc/meminfo` | حافظه |
| `/proc/net/dev` | ترافیک |
| `/proc/diskstats`، `/proc/loadavg`، `/proc/uptime` | بقیه |

هسته VMkernel هیچ‌کدام را ندارد — `/proc` در ESXi ساختار کاملاً دیگری
دارد. ضمناً ESXi نه systemd دارد و نه فایل‌سیستم ماندگار برای چنین
چیزی؛ هرچه بنویسید با ریبوت می‌پرد.

**پس چیزی روی خود ESXi نصب نمی‌شود.**

## به‌جایش چه می‌شود

`/api/ingest` فقط یک POST جیسون با توکن است و برایش مهم نیست داده از
کجا آمده. جمع‌کننده روی **سرور پنل** می‌نشیند، با SNMP از ESXi آمار
می‌خواند و با توکن همان سرور می‌فرستد:

```
سرور پنل ──SNMP/161──> هاست ESXi
    │
    └──HTTPS──> /api/ingest
```

برای پنل هیچ فرقی با یک سرور معمولی ندارد: نمودار، آمار ماهانه، ترافیک
پیش‌خرید، هشدار قطعی — همه کار می‌کنند.

**دسترسی فقط خواندنی است.** جمع‌کننده جز `GetRequest` و
`GetNextRequest` چیزی نمی‌فرستد و `SetRequest` اصلاً پیاده نشده.
`scripts/test-snmp.py` این را قفل کرده: همه فراخوانی‌های `_exchange` را
پیدا می‌کند و اگر نوع پیام دیگری ببیند شکست می‌دهد.

## قدم ۱ — فعال‌کردن SNMP روی ESXi

با SSH به هاست وصل شوید (یا از ESXi Shell). **این تنها تغییری است که
روی هاست انجام می‌شود.**

نام جامعه را عوض کنید؛ `public` نگذارید:

```bash
esxcli system snmp set --communities pasargad_ro
```

```bash
esxcli system snmp set --enable true
```

بررسی وضعیت:

```bash
esxcli system snmp get
```

اگر فایروال ESXi جلوی SNMP را گرفته باشد:

```bash
esxcli network firewall ruleset set --ruleset-id snmp --enabled true
```

**نام جامعه مثل گذرواژه است** — هرکس بداند می‌تواند آمار هاست را
بخواند. فقط از آی‌پی سرور پنل اجازه بدهید. در دیتاسنتر، پورت ۱۶۱ UDP
نباید از اینترنت باز باشد.

## قدم ۲ — ساخت سرور در پنل

در «سرورهای اختصاصی» سرور تازه بسازید. آی‌پی اصلی را همان آی‌پی مدیریتی
هاست بگذارید. توکن ایجنت را از همان صفحه بردارید — در کادر نصب، زبانه
«VMware ESXi» را بزنید.

## قدم ۳ — اول ببینید هاست چه دارد

روی **سرور پنل**:

```bash
curl -fsSL -o /usr/local/bin/esxi-agent.py https://panel.example.com/agent/esxi-agent.py
```

```bash
python3 /usr/local/bin/esxi-agent.py --host 192.168.10.5 --community pasargad_ro --probe
```

این فقط می‌خواند و چاپ می‌کند. چیزی به پنل نمی‌رود و چیزی روی هاست عوض
نمی‌شود.

خروجی چهار بخش دارد: شناسنامه، رابط‌های شبکه، پردازنده، و حافظه و
ذخیره‌سازی. آخرش می‌گوید کدام ردیف را به‌عنوان حافظه و کدام را
به‌عنوان دیسک انتخاب کرده.

**این قدم را رد نکنید.** نسخه‌های مختلف ESXi جدول‌های متفاوتی پر
می‌کنند؛ باید ببینید رابط آپلینک شما `vmnic0` است یا چیز دیگر، و
انتخاب دیتااستور درست است یا نه.

## قدم ۴ — یک بار آزمایشی بفرستید

```bash
python3 /usr/local/bin/esxi-agent.py \
  --host 192.168.10.5 --community pasargad_ro \
  --url https://panel.example.com --token <توکن-سرور> \
  --iface vmnic0 --once
```

در صفحه سرور باید «آخرین ارتباط: چند لحظه پیش» ببینید.

## قدم ۵ — سرویس دائمی

روی سرور پنل:

```bash
cat > /etc/systemd/system/pasargad-esxi.service <<'EOF'
[Unit]
Description=Pasargad ESXi collector
After=network-online.target

[Service]
ExecStart=/usr/bin/python3 /usr/local/bin/esxi-agent.py \
  --host 192.168.10.5 --community pasargad_ro \
  --url https://panel.example.com --token TOKEN_HERE \
  --iface vmnic0 --interval 30
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF
```

```bash
systemctl daemon-reload && systemctl enable --now pasargad-esxi
```

```bash
journalctl -u pasargad-esxi -f
```

**چند هاست ESXi؟** برای هر کدام یک واحد سرویس با نام جدا بسازید
(`pasargad-esxi-2.service` و...). هر کدام توکن سرور خودش را می‌گیرد.

## گزینه‌ها

| گزینه | معنی |
|---|---|
| `--host` | آی‌پی مدیریتی ESXi |
| `--community` | نام جامعه SNMP فقط‌خواندنی |
| `--iface` | رابط آپلینک؛ چند تا با ویرگول، ترافیکشان جمع می‌شود |
| `--disk-match` | بخشی از نام دیتااستوری که فضایش گزارش شود |
| `--interval` | فاصله ارسال، پیش‌فرض ۳۰ ثانیه |
| `--insecure` | گواهی TLS پنل بررسی نشود (گواهی خودامضا) |
| `--probe` | فقط بخوان و نشان بده |
| `--once` | یک بار بفرست و خارج شو |

**آپلینک باندشده:** اگر هاست دو کارت شبکه در تیم دارد، هر دو را بدهید —
`--iface vmnic0,vmnic1`. با دادن یکی، نصف ترافیک شمرده نمی‌شود و
صورتحساب مشتری کمتر از واقعیت درمی‌آید.

---

## چه چیزی گزارش می‌شود و چه چیزی نه

| در پنل | از کجا | اگر هاست نداشته باشد |
|---|---|---|
| ترافیک | `ifHCInOctets` / `ifHCOutOctets` | واپسین: شمارنده ۳۲ بیتی، با هشدار |
| پردازنده | `hrProcessorLoad` (میانگین هسته‌ها) | گزارش نمی‌شود |
| حافظه | `hrStorage`، ردیف Real Memory | گزارش نمی‌شود |
| دیسک | `hrStorage`، بزرگ‌ترین دیتااستور | گزارش نمی‌شود |
| آپ‌تایم | `hrSystemUptime` | واپسین: `sysUpTime` |
| بالا/پایین | خودِ رسیدن گزارش | — |

**نبودِ هر کدام هشدار می‌دهد و بقیه کار می‌کنند.** فیلدی که هاست ندارد
اصلاً فرستاده نمی‌شود — نه اینکه صفر برود. صفر در نمودار مثل «مصرف
نداشت» دیده می‌شود، و آن دروغ است.

**بالا/پایین** کد تازه‌ای لازم ندارد: اگر جمع‌کننده نتواند از هاست
بخواند، عمداً چیزی به پنل نمی‌فرستد. پنل خودش با `last_seen_at` سرور را
قطع تشخیص می‌دهد — که همان واقعیت است.

## آنچه گزارش نمی‌شود

- **بار سیستم (load)** — SNMP معادلی ندارد
- **ورودی/خروجی دیسک** — `hrStorage` فقط فضاست، نه سرعت
- **تعداد پردازه و اتصال** — بی‌معنی روی هایپروایزر
- **فهرست ماشین‌های مجازی** — با SNMP نمی‌شود؛ vSphere API لازم دارد

اگر فهرست VMها را خواستید، آن مسیر جداست: یک کاربر فقط‌خواندنی vSphere
و کلاینت SOAP. آن وقت رمز باید در پنل بماند — به همین دلیل فعلاً نرفتیم
سراغش.

## اشکال‌زدایی

**«هاست پاسخ نداد»**

```bash
esxcli system snmp get
```

روی سرور پنل، باز بودن مسیر را ببینید:

```bash
python3 /usr/local/bin/esxi-agent.py --host 192.168.10.5 --community pasargad_ro --probe
```

اگر باز هم چیزی نیامد: فایروال ESXi، فایروال دیتاسنتر، یا نام جامعه
اشتباه. SNMP روی UDP است، پس `ping` جواب‌دادن چیزی را ثابت نمی‌کند.

**«این رابط‌ها روی هاست نیستند»** — جمع‌کننده فهرست موجود را چاپ می‌کند.
نام درست را از همان بردارید.

**«هاست فقط شمارنده ۳۲ بیتی دارد»** — شمارنده ۳۲ بیتی روی پیوند یک
گیگابیتی هر حدود ۳۴ ثانیه سرریز می‌کند. `--interval` را زیر ۲۰ ثانیه
بگذارید، وگرنه ترافیک کمتر از واقعیت شمرده می‌شود.

**عدد ترافیک با انتظار نمی‌خواند** — احتمالاً رابط اشتباه است یا هاست
آپلینک باندشده دارد. `--probe` حجم تجمعی هر رابط را نشان می‌دهد؛ آن که
بزرگ‌ترین عدد را دارد معمولاً آپلینک واقعی است.

## آزمون

`scripts/test-snmp.py` — کدک BER را در برابر بایت‌های دستی‌محاسبه‌شده
بررسی می‌کند، یک پاسخ کامل SNMP می‌سازد و باز می‌کند، و قفل می‌کند که
هیچ مسیر نوشتنی در جمع‌کننده نباشد.

دو موردی که به‌راحتی غلط می‌شوند و اینجا قفل شده‌اند:

- شمارنده ۶۴ بیتی باید **بی‌علامت** خوانده شود. علامت‌دار، ترافیک یک
  هاست پرمصرف را عدد منفی می‌کند.
- عدد مثبتی که بیت بالایش یک است، در BER بایت صفر جلویی می‌خواهد. بدون
  آن شناسه درخواست منفی رمز می‌شود و هاست پاسخ نمی‌دهد.
