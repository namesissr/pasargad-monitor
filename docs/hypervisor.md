# نصب ایجنت روی نود مجازی‌ساز (SolusVM و Virtualizor با KVM)

خلاصه: **ایجنت با SolusVM و Virtualizor تداخل ندارد و به وی‌پی‌اس‌ها دست نمی‌زند.**
ولی چند عدد روی نود مجازی‌ساز نیاز به تنظیم دارند، چون شبکه و دیسک نود با یک سرور معمولی فرق می‌کند.

---

## چرا تداخل ندارد

ایجنت فقط **می‌خواند** و هیچ چیزی را تغییر نمی‌دهد:

| کاری که انجام می‌دهد | کاری که انجام نمی‌دهد |
|---|---|
| خواندن `/proc/stat`، `/proc/meminfo`، `/proc/net/dev`، `/proc/diskstats`، `/proc/loadavg` | دست‌زدن به آی‌پی‌تیبلز یا پیکربندی شبکه |
| `statvfs` روی یک مسیر | دست‌زدن به libvirt، qemu یا دیسک مهمان‌ها |
| یک درخواست HTTPS خروجی هر ۱۰ ثانیه | باز کردن هیچ پورتی برای شنیدن |
| نوشتن لاگ در journald | نوشتن هیچ فایلی جز لاگ خودش |

- **هیچ پورتی باز نمی‌کند.** فقط اتصال خروجی به پنل دارد.
- **نام سرویس `pasargad-agent` است** و با `solusvm-*`، `virtualizor` و `vpsdaemon` تداخل اسمی ندارد.
- **کاربر جدیدی نمی‌سازد** و به `sudoers` دست نمی‌زند.
- سرویس با `Nice=19`، `IOSchedulingClass=idle`، `CPUQuota=5%` و سقف حافظه ۱۲۸ مگابایت اجرا می‌شود. یعنی هر وقت نود شلوغ باشد، ایجنت آخرین چیزی است که پردازنده می‌گیرد.

مصرف واقعی: حدود ۲۰ مگابایت حافظه و کسری از یک درصد پردازنده.

**تنها خواندن نسبتاً سنگین** `/proc/net/tcp` است که اندازه‌اش با تعداد سوکت‌های خودِ نود رابطه دارد. در حالت بریج، ترافیک مهمان‌ها در لایه دو رد می‌شود و سوکتی روی هاست نمی‌سازد، پس این عدد روی نود مجازی‌ساز کوچک می‌ماند.

**تنها چیزی که نصب می‌کند** پایتون ۳ است، آن هم فقط اگر نباشد. روی سنت‌اواس ۷ و آلما و اوبونتو معمولاً از قبل هست. اگر روی نود بسته‌ها پین شده‌اند، اول دستی نصبش کنید تا اسکریپت سراغ مدیر بسته نرود.

---

## سه عددی که روی نود مجازی‌ساز فرق می‌کنند

### ۱. ترافیک — مهم‌ترین مورد

روی نود KVM با شبکه بریج:

```
eth0   ← کارت فیزیکی: ترافیک هاست + همه وی‌پی‌اس‌ها (همان چیزی که دیتاسنتر صورتحساب می‌دهد)
br0    ← بریج: آی‌پی خود نود اینجاست
vnet0  ← تپ وی‌پی‌اس اول
vnet1  ← تپ وی‌پی‌اس دوم
...
```

اگر همه اینها جمع شوند، ترافیک **سه تا پنج برابر** واقعی درمی‌آید. اگر فقط بریج شمرده شود، ترافیک وی‌پی‌اس‌ها **جا می‌افتد**.

ایجنت این را خودکار حل می‌کند: از رابط مسیر پیش‌فرض شروع می‌کند و با `lower_*` در sysfs به لایه پایین می‌رود تا به کارت فیزیکی برسد، و رابط‌های مهمان را کنار می‌گذارد.

```
br0 → eth0                  بریج ساده
br0 → bond0 → eth0, eth1    بریج روی باند
eth0.100 → eth0             ولن
```

**قبل از اعتماد به عدد، روی هر نود این را اجرا کنید:**

```bash
python3 /usr/local/bin/pasargad-agent.py --list-ifaces
```

خروجی نشان می‌دهد کدام رابط شمرده می‌شود. اگر درست نبود، دستی مشخصش کنید:

```bash
curl -fsSL https://panel.example.com/agent/install.sh | \
  bash -s -- https://panel.example.com TOKEN --iface eth0
```

اسکریپت نصب اگر نود مجازی‌ساز را تشخیص دهد، همین جدول را خودش نشان می‌دهد.

نام رابط انتخاب‌شده در پنل، صفحه سرور، بخش «مشخصات» با عنوان **رابط شمرده‌شده** دیده می‌شود. اگر آنجا `br0` یا `vnet3` نوشته بود، انتخاب اشتباه است.

### ۲. پردازنده

روی نود KVM، وقتی که صرف مهمان‌ها می‌شود در فیلد `guest` گزارش می‌شود ولی کرنل آن را **از قبل داخل `user` هم شمرده**. جمع‌زدن ساده همه فیلدها یعنی دوباره‌شماری و درصد پردازنده کمتر از واقع.

ایجنت فقط هشت فیلد اول `/proc/stat` را جمع می‌کند، پس عدد درست است.

### ۳. دیسک

`--disk` پیش‌فرض روی `/` است، یعنی پارتیشن سیستم‌عامل نود که معمولاً کوچک است — نه فضای وی‌پی‌اس‌ها.

اگر دیسک وی‌پی‌اس‌ها روی یک فایل‌سیستم است، مسیرش را بدهید:

```bash
--disk /var/lib/libvirt/images     # نصب معمول KVM
--disk /home                       # چیدمان رایج Virtualizor
```

**اگر از LVM یا LVM-thin استفاده می‌کنید — که پیش‌فرض SolusVM و Virtualizor است — فضای وی‌پی‌اس‌ها اصلاً فایل‌سیستم نیست و `statvfs` آن را نمی‌بیند.** در این حالت درصد دیسکی که پنل نشان می‌دهد فقط مربوط به پارتیشن سیستم‌عامل است. برای پایش فضای گروه حجم، فعلاً باید از `vgs` روی خود نود استفاده کنید؛ ایجنت این را گزارش نمی‌کند.

آمار ورودی و خروجی دیسک (`/proc/diskstats`) درست است: فقط دیسک‌های کامل شمرده می‌شوند و `dm-*` که حجم‌های وی‌پی‌اس‌اند کنار گذاشته می‌شوند تا دوباره‌شماری نشود.

## دستور پیشنهادی برای نود مجازی‌ساز

```bash
curl -fsSL https://panel.example.com/agent/install.sh | \
  bash -s -- https://panel.example.com TOKEN --iface eth0 --disk /var/lib/libvirt/images
```

`eth0` و مسیر دیسک را با مقدار واقعی نود عوض کنید.

## پایش آی‌پی وی‌پی‌اس‌ها

می‌توانید همه آی‌پی‌های نود را در پنل وارد کنید، ولی **گزینه «پینگ دوره‌ای» را برای آی‌پی مشتری‌ها روشن نکنید** مگر عمداً بخواهید.

دلیلش: خیلی از مشتری‌ها ICMP را روی فایروال وی‌پی‌اسشان می‌بندند، یا وی‌پی‌اس را خاموش می‌گذارند. نتیجه‌اش رویداد قطعی برای آی‌پی‌هایی است که هیچ مشکلی ندارند — و هشداری که مدام کاذب باشد، خیلی زود نادیده گرفته می‌شود.

پیشنهاد: پینگ را فقط برای آی‌پی خود نود و آی‌پی‌های سرویس‌های خودتان روشن کنید. بقیه آی‌پی‌ها فقط برای فهرست و تخصیص ثبت شوند.

اگر خود نود قطع شود، پنل آی‌پی‌های آن نود را پینگ نمی‌کند — وگرنه یک نود قطع، ده‌ها هشدار می‌ساخت.

---

## حذف ایجنت

```bash
systemctl disable --now pasargad-agent
rm -f /etc/systemd/system/pasargad-agent.service /usr/local/bin/pasargad-agent.py
systemctl daemon-reload
```

هیچ اثر دیگری روی نود باقی نمی‌ماند.
